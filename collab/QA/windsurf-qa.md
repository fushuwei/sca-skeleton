## 潜在问题与建议

### 1. P-10 修复方案不够完善

**当前方案**：前端 revoke 失败时 `console.warn` 记录日志

**问题**：
- `console.warn` 在生产环境可能被用户忽略
- 未提供用户反馈，用户可能认为已登出但实际未登出

**建议**：
```typescript
// 当前方案
console.warn("Token revoke failed:", error);

// 建议方案
if (!revokeSuccess) {
  showToast("登出异常，请清除浏览器缓存后重新登录", "warning");
  console.warn("Token revoke failed:", error);
}
```

### 2. P-21 修复需要运行时验证

**当前方案**：直接移除 `spring-boot-starter-session-data-redis` 依赖

**风险**：
- 报告中提到需验证 `RedisOAuth2AuthorizationService` 是否间接依赖 Spring Session 的 Redis 序列化机制
- 如果存在间接依赖，移除后可能导致序列化失败

**建议**：
- 在修复前先运行应用，检查是否有 `SessionRepository` 相关 Bean
- 或先注释掉依赖，启动验证后再删除

### 3. P-19 修复可能过于激进

**当前方案**：移除冗余的 `authorization_code` 转换器注册

**问题**：
- 报告中提到"可保留作为向后兼容的基础设施"
- 移除后如果未来需要支持授权码模式，需要重新添加

**建议**：
- 保留转换器但添加注释说明："保留作为向后兼容，当前密码模式不使用"
- 或在文档中记录移除原因，便于未来追溯

### 4. P-26 修复可能过度设计

**当前方案**：新增 `VITE_OAUTH_SCOPE` 环境变量

**问题**：
- scope 值 `"profile all"` 在两个 SPA 中完全一致
- 环境变量增加配置复杂度，但实际灵活性提升有限

**建议**：
- 保持硬编码，在代码注释中说明 scope 值
- 或仅在需要不同 scope 时才引入环境变量

### 5. P-12 修复方案可能不够优雅

**当前方案**：`username.value += e.key`

**问题**：
- 仍然绕过了 Vue 的响应式系统直接修改值
- 可能导致输入法行为异常

**建议**：
```typescript
// 更优雅的方案
const input = usernameInput.value;
if (!input) return;
input.focus();
// 让浏览器自然处理按键，不手动拼接
```

### 6. 修复验证清单不够完整

**当前清单**：9 项验证

**缺失项**：
- 验证 P-14 修复：用户不存在和密码错误是否返回相同错误消息
- 验证 P-20/P-23 修复：JSON 响应是否正确转义特殊字符
- 验证 P-29 修复：`getServletPath()` 在有 context-path 的场景下是否正确

**建议**：补充 3 项验证
