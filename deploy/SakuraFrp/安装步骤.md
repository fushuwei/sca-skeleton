# SakuraFrp 内网穿透部署步骤

**穿透目标：** Nginx 8080 端口（反代网关 9999，托管 Admin / Portal 前端） **访问地址：** `https://newease.cloud:49480`（TCP
隧道必须带端口）

## 一、SakuraFrp 配置（Web 面板）

### 1.1 获取访问密钥

登录 [管理面板](https://www.natfrp.com/user/)，点击「复制访问密钥」。

### 1.2 创建 TCP 隧道

进入 **服务 → 隧道列表 → 创建隧道**：

| 配置项   | 值                    | 说明                                       |
|----------|-----------------------|--------------------------------------------|
| 隧道类型 | TCP                   | HTTP 隧道没有自动 HTTPS 功能               |
| 节点     | 长沙电信PLUS2（建站） | 实际可用节点以面板为准，选带「建站」标识的 |
| 本地 IP  | 本地主机 (127.0.0.1)  | 下拉选择                                   |
| 本地端口 | 8080                  | Nginx 容器端口                             |
| 远程端口 | 留空                  | 系统自动分配（当前为 49480）               |

### 1.3 配置自动 HTTPS

隧道创建后，在隧道列表点击该隧道展开编辑面板：

- **自动 HTTPS**：填入 `newease.cloud`

保存后 frpc 启动时会自动生成 `newease.cloud.crt` 和 `newease.cloud.key` 自签证书。

### 1.4 记录隧道信息

在隧道列表确认：

- 隧道 ID（当前 `28442930`）
- 节点域名（当前 `frp-oil.com`，以 frpc 启动日志为准）
- 远程端口（当前 `49480`）

## 二、服务器部署

### 2.1 下载 frpc

在 [软件下载](https://www.natfrp.com/download/) 页面获取 Linux amd64 版 frpc 下载链接：

```bash
wget -O /usr/local/bin/frpc <下载链接>
chmod 755 /usr/local/bin/frpc
frpc -v   # 验证：0.51.0-sakura-14
```

### 2.2 创建工作目录

```bash
mkdir -p /usr/local/etc/natfrp
```

### 2.3 创建 systemd 服务

```bash
cat > /etc/systemd/system/frpc@.service << 'EOF'
[Unit]
Description=SakuraFrp frpc Service
After=network.target

[Service]
Type=idle
Restart=on-failure
RestartSec=60s
ExecStart=/usr/local/bin/frpc -f %i
WorkingDirectory=/usr/local/etc/natfrp

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
```

### 2.4 启动隧道

```bash
# 格式：frpc@<访问密钥>:<隧道ID>
systemctl start frpc@<访问密钥>:28442930
systemctl enable frpc@<访问密钥>:28442930
```

### 2.5 确认启动成功

```bash
journalctl -u frpc@<访问密钥>:28442930 -n 20
```

正常日志：

```
已为 newease.cloud 生成自签证书, 保存到 /usr/local/etc/natfrp
TCP 隧道启动成功
使用 >>frp-oil.com:49480<< 连接你的隧道
```

## 三、DNS 配置（阿里云）

在 [云解析 DNS 控制台](https://dnsnext.console.aliyun.com/) 为 `newease.cloud` 添加两条 CNAME 记录：

| 主机记录 | 记录类型 | 记录值        | TTL  |
|----------|----------|---------------|------|
| `@`      | CNAME    | `frp-oil.com` | 默认 |
| `www`    | CNAME    | `frp-oil.com` | 默认 |

> 节点域名以 frpc 启动日志中 `使用 >>xxx<< 连接你的隧道` 为准，不同节点域名不同。

验证生效：

```bash
dig +short newease.cloud @223.5.5.5
# 期望：frp-oil.com. → 节点 IP
```

## 四、SSL 证书（消除浏览器不安全警告）

自动 HTTPS 默认使用自签证书，浏览器会提示不安全。替换为受信任证书：

### 4.1 申请证书

在 [阿里云数字证书管理服务](https://yundun.console.aliyun.com/?p=cas) 申请免费 DV 证书（域名 `newease.cloud`，DNS 验证），下载
**Nginx 格式**，得到 `.pem`（证书）和 `.key`（私钥）。

### 4.2 替换证书

```bash
systemctl stop frpc@<访问密钥>:28442930

# 文件名必须与自动 HTTPS 填写的域名一致
cp your-cert.pem /usr/local/etc/natfrp/newease.cloud.crt
cp your-cert.key /usr/local/etc/natfrp/newease.cloud.key
chmod 644 /usr/local/etc/natfrp/newease.cloud.crt
chmod 600 /usr/local/etc/natfrp/newease.cloud.key

systemctl start frpc@<访问密钥>:28442930
```

> 如果重启后证书又变回自签，说明证书格式有误（检查证书链是否完整、私钥是否匹配）。

## 五、验证

```bash
# 首页（200）
curl -I https://newease.cloud:49480/

# Admin（301 → /admin/）
curl -I https://newease.cloud:49480/admin

# API 健康检查（200）
curl -I https://newease.cloud:49480/api/actuator/health
```

## 六、运维命令

```bash
# 状态 / 启动 / 停止 / 重启
systemctl status  frpc@<访问密钥>:28442930
systemctl start   frpc@<访问密钥>:28442930
systemctl stop    frpc@<访问密钥>:28442930
systemctl restart frpc@<访问密钥>:28442930

# 实时日志
journalctl -u frpc@<访问密钥>:28442930 -f

# 前台调试（先停服务）
frpc -f <访问密钥>:28442930
```

## 已知问题

**/admin 重定向丢端口：** Nginx 配置 `return 301 https://$host/admin/` 中 `$host` 不含端口， 导致跳转到
`https://newease.cloud/admin/`（缺少 `:49480`）。
修复：改为 `return 301 https://$http_host/admin/;`（`$http_host` 保留 Host 头中的端口）。
