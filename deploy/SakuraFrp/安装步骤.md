## 二、Linux 服务器部署

### 2.1 下载 frpc

> 在 [软件下载](https://www.natfrp.com/tunnel/download) 页面获取 Linux amd64 版 frpc 下载链接：

```bash
wget -O /usr/local/bin/frpc https://nya.globalslb.net/natfrp/client/frpc/0.51.0-sakura-14/frpc_linux_amd64
chmod 755 /usr/local/bin/frpc
frpc -v
```

### 2.2 创建工作目录

```bash
mkdir -p /usr/local/etc/natfrp
```

### 2.3 创建 systemd 服务

```bash
cat > /etc/systemd/system/frpc@.service << 'EOF'
[Unit]
Description=SakuraFrp frpc Service
After=network.target

[Service]
Type=idle
Restart=on-failure
RestartSec=60s
ExecStart=/usr/local/bin/frpc -f %i
WorkingDirectory=/usr/local/etc/natfrp

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
```

### 2.4 启动隧道

> 格式：frpc@<访问密钥>:<隧道ID>

```bash
systemctl start frpc@v7bx44tsklorvz141rmou651sd82csuu:28471369
systemctl enable frpc@v7bx44tsklorvz141rmou651sd82csuu:28471369
```

### 2.5 确认启动成功

```bash
journalctl -u frpc@v7bx44tsklorvz141rmou651sd82csuu:28471369 -n 20
```

正常日志：


## 四、SSL 证书

> 自动 HTTPS 默认使用自签证书，浏览器会提示不安全。需替换为受信任证书

### 4.1 申请证书

> 在 [阿里云数字证书管理服务](https://yundun.console.aliyun.com/?p=cas) 申请 **个人测试证书**（域名 `newease.cloud`，DNS

### 4.2 替换证书

```bash

systemctl stop frpc@v7bx44tsklorvz141rmou651sd82csuu:28471369

# 2. 备份旧的自签证书
mv /usr/local/etc/natfrp/newease.cloud.crt /usr/local/etc/natfrp/newease.cloud.crt.bak

cp ~/26339518_newease.cloud_nginx/newease.cloud.key /usr/local/etc/natfrp/newease.cloud.key

# 4. 修正权限
chmod 755 /usr/local/etc/natfrp/newease.cloud.crt
chmod 755 /usr/local/etc/natfrp/newease.cloud.key

# 5. 启动隧道服务
systemctl start frpc@v7bx44tsklorvz141rmou651sd82csuu:28471369
```

## 六、获取访问者真实 IP（Proxy Protocol v2）

> **必须配置，否则登录日志的 IP 全是 Docker 网桥网关 `172.18.0.1`、位置显示"内网IP"。**

### 6.1 为什么会变成 172.18.0.1

流量路径：`浏览器 → SakuraFrp 节点(TLS 终结) → frpc(宿主机) → Docker 端口映射(8080:8080) → docker-proxy(SNAT) → Nginx 容器 → 网关 → 业务服务`

- 本隧道是 **HTTPS 隧道**，frpc 到本地 Nginx 之间是纯 TCP 连接。SakuraFrp 的 `X-Forwarded-For` 头方案**仅适用于 HTTP 隧道**，HTTPS 隧道不会通过 HTTP 头传真实 IP。
- frpc 在宿主机上，连接到 Nginx 容器要经过 Docker 端口映射的 `docker-proxy`，它做了 **SNAT**：把源 IP 改写为 Docker 网桥网关 `172.18.0.1`，而不是真实客户端 IP。
- 于是 Nginx 的 `$remote_addr` 全是 `172.18.0.1`，无论你用 5G 流量还是内网访问都一样（frpc 是公网连接的终点，它向本地 Nginx 重新发起本地连接，TCP 源 IP 永远是本机地址）。Nginx 再把它当作真实 IP 透传给网关 → 认证服务，最终登录日志记录的 IP 就是 `172.18.0.1`，ip2region 判定为内网 → 位置"内网IP"。

验证根因：

```bash
docker exec nginx tail -20 /var/log/nginx/sca-skeleton.access.log
# access.log 第一个字段（$remote_addr）当前一定是 172.18.0.1
```

### 6.2 解决方案：Proxy Protocol v2

参考 [SakuraFrp 官方文档 · 获取访问者的真实 IP](https://doc.natfrp.com/bestpractice/realip.html)。Proxy Protocol 适用于 TCP/UDP/HTTP/HTTPS 隧道，在 TCP 握手后发送一个协议头携带真实客户端 IP。docker-proxy 是透明 TCP 字节转发，PROXY Protocol 头会原样透传进 Nginx 容器。

#### 第 1 步：frpc 隧道开启 Proxy Protocol

在 [SakuraFrp 管理面板](https://www.natfrp.com/user/) 编辑隧道，开启「高级用户模式」，在**隧道自定义设置**中添加：

```
proxy_protocol_version = v2
```

> 保存后重启隧道：`systemctl restart frpc@v7bx44tsklorvz141rmou651sd82csuu:28471369`

#### 第 2 步：Nginx 已就绪（本仓库已配置）

- `conf/nginx.conf`：http 块已加 `set_real_ip_from` + `real_ip_header proxy_protocol`，信任本机回环与 Docker 私有网段，realip 模块据此把 `$remote_addr` 覆盖为真实客户端 IP。
- `conf.d/sca-skeleton-prod.conf`（及 `sca-skeleton.conf`）：`listen 8080` 已加 `proxy_protocol`。

> 前提：Nginx 镜像须含 `http_realip_module`（官方 `nginx:stable` 默认已编译）。验证：
> ```bash
> docker exec nginx nginx -V 2>&1 | grep -o 'http_realip_module'
> ```
> 若无输出，需更换为官方 nginx 镜像或自编译带该模块的镜像。

#### 第 3 步：重新加载 Nginx

```bash
# 先校验语法（必须 OK 才能 reload）
docker exec nginx nginx -t
docker exec nginx nginx -s reload
```

#### 第 4 步：验证

用 5G 流量（非本机/非局域网）访问 `https://newease.cloud/admin` 登录，查看登录日志：

```bash
docker exec nginx tail -f /var/log/nginx/sca-skeleton.access.log
```

- access.log 的第一个字段（`$remote_addr`）应为真实公网 IP，不再是 `172.18.0.1`。
- 后台「登录日志」页的 IP 应为真实公网 IP，位置显示省份/城市而非"内网IP"。

### 6.3 注意事项

- **frpc 与 Nginx 必须同时开启**，否则隧道不可用。只改了一边会导致 `https://newease.cloud` 打不开（Nginx 收到的不是 PROXY Protocol 头会直接断开连接）。
- 启用 `proxy_protocol` 后，**浏览器直连 `192.168.1.105:8080` 会失败**（该端口强制要求 PROXY Protocol 握手）。外网经 SakuraFrp 隧道访问不受影响。需要本地/内网直连 Nginx，请使用 SakuraFrp 的[「内网访问」功能](https://doc.natfrp.com/frpc/manual.html#feature-local-access)。
- 部署到服务器的站点配置必须是带 `proxy_protocol` 的版本（`sca-skeleton-prod.conf` 或 `sca-skeleton.conf`），不要混用未修改的配置。
