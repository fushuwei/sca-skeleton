# Cloudflare Tunnel 部署步骤（ThinkPad Ubuntu Server）

> 目标：把本机 Nginx:80 通过 Cloudflare Tunnel 暴露到 `https://newease.cloud`，
> 无需公网 IP、无需开放防火墙端口、流量全程 TLS。
>
> 单域名单入口架构：`newease.cloud` 所有路径统一打到 Nginx:80，由 Nginx 做
> `/admin/`、`/`、`/api/`、`/auth/` 二次分流（复用 prod/nginx 配置，无需改造）。

---

## 替换清单 ⚠ 必看

本方案中**只有一处占位符需要你手动替换**，替换后配置即可直接使用：

| 占位符 | 替换为 | 出现位置 |
| --- | --- | --- |
| `<YOUR_TUNNEL_UUID>` | 第三步 `cloudflared tunnel create` 返回的 UUID | `config.yml` 第 13、14 行（共 2 处） |

> 替换前请不要直接执行 `cloudflared service install`，会因 UUID 不匹配而失败。

---

## 0. 前置条件

1. **Nginx 已部署并运行**：`curl -I http://localhost:80` 能返回 200（前端 dist 已就位）。
2. **拥有 Cloudflare 账号且 `newease.cloud` 已托管到 Cloudflare**（NS 已指向 Cloudflare）。
3. **本机有浏览器**（用于 `cloudflared tunnel login` 授权）。
   纯命令行场景可先在本地（macOS）装 cloudflared 跑 `login`，再把生成的
   `~/.cloudflared/cert.pem` 上传到服务器 `/root/.cloudflared/cert.pem`。

---

## 1. 安装 cloudflared（你已完成，跳过）

```bash
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared-linux-amd64.deb
cloudflared --version
```

验证：`cloudflared --version` 能输出版本号即可。

---

## 2. 登录 Cloudflare 账号

```bash
cloudflared tunnel login
```

- 控制台输出一个 `https://dash.cloudflare.com/argotunnel?...` URL
- 复制到浏览器打开 → 登录 Cloudflare → 选择 `newease.cloud` 这个 zone 授权
- 授权成功后服务器生成：`/root/.cloudflared/cert.pem`

验证：
```bash
ls -l /root/.cloudflared/cert.pem
```

---

## 3. 创建隧道

```bash
cloudflared tunnel create sca-skeleton
```

输出示例：
```
Created tunnel sca-skeleton with id  a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx
Tunnel credentials written to /root/.cloudflared/a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx.json
```

**记下这个 UUID**（下文用 `<YOUR_TUNNEL_UUID>` 代指）。

查看隧道列表确认：
```bash
cloudflared tunnel list
```

---

## 4. 部署 config.yml

```bash
# 4.1 创建目录（已存在则跳过）
mkdir -p /root/.cloudflared/

# 4.2 在本地（macOS）上传 config.yml 到服务器
#     scp deploy/cloudflared/config.yml root@192.168.1.105:/root/.cloudflared/config.yml

# 4.3 替换占位符（替换清单第 1 行，共 2 处）
#     把下面 UUID 换成你第三步拿到的真实值
sed -i "s|<YOUR_TUNNEL_UUID>|a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx|g" /root/.cloudflared/config.yml

# 4.4 验证替换结果（两处 UUID 必须一致，且与 .json 文件名一致）
grep -E "tunnel:|credentials-file" /root/.cloudflared/config.yml
ls /root/.cloudflared/*.json
```

预期：
```
tunnel: a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx
credentials-file: /root/.cloudflared/a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx.json
```

---

## 5. 配置 DNS 解析

为 `newease.cloud` 创建 CNAME 记录指向隧道：

```bash
cloudflared tunnel route dns sca-skeleton newease.cloud
```

- 命令成功后，Cloudflare DNS 会自动新增一条 CNAME：`newease.cloud → <UUID>.cfargotunnel.com`
- 到 https://dash.cloudflare.com DNS 面板可看到这条记录（橙色云朵代理开启）

> 若 `newease.cloud` 已有 A/AAAA 记录会冲突，需先在面板删除旧记录。

## 6. 手动测试运行

先手动跑一次，确认无报错再注册系统服务：

```bash
cloudflared tunnel run sca-skeleton
```

预期日志看到 `Registered tunnel connection`（一般 4 条连接）即正常。
浏览器访问 `https://newease.cloud/` 验证页面能打开。
按 `Ctrl+C` 退出。

---

## 7. 注册为系统服务（开机自启）

```bash
# 7.1 自动生成 systemd 单元 + 拷贝 config.yml 到 /etc/cloudflared/
sudo cloudflared service install

# 7.2 启用并启动
sudo systemctl enable cloudflared
sudo systemctl start cloudflared

# 7.3 查看状态
sudo systemctl status cloudflared
```

预期 `active (running)`。

> `cloudflared service install` 内部行为：
> 1. 把 `/root/.cloudflared/config.yml` 拷贝到 `/etc/cloudflared/config.yml`
> 2. 自动生成 `/etc/systemd/system/cloudflared.service`（无需手写单元文件）
> 3. 注册到 systemd
>
> 因此**本方案不包含手写 cloudflared.service 文件**，由 `service install` 命令自动生成。

## 10. 关键设计说明（审核重点）

1. **单域名单入口**：所有流量走 `newease.cloud → Nginx:80`，Nginx 内部做 `/admin/`、`/`、`/api/`、`/auth/` 二次分流。复用 prod/nginx 配置，零改造。
2. **不开放公网端口**：cloudflared 只出站连接 Cloudflare 边缘节点，无需在防火墙开 80/443，比传统反向代理更安全。Nginx 容器的 80 端口也只在宿主机本地监听，外网无法直接访问。
3. **systemd 托管**：`cloudflared service install` 自动生成单元文件，开机自启、异常重启。
4. **config.yml 路径约定**：
   - 编辑位置：`/root/.cloudflared/config.yml`（第五步手动放）
   - 运行位置：`/etc/cloudflared/config.yml`（第七步 `service install` 自动拷贝）
   - 凭证文件位置：`/root/.cloudflared/<UUID>.json`（第三步 `tunnel create` 自动生成）
5. **catch-all 404**：ingress 最后一条 `service: http_status:404`，未匹配 Host 直接拒绝，防止裸跑其它域名。

## 11. ⚠ 重要提醒：前端与后端需同步调整

cloudflared 把外网入口从 `192.168.1.105` 变成 `https://newease.cloud`，OAuth2 / 前端相关配置需要相应更新（这些是代码层面，需你手动改，本方案只列清单）：

1. **前端 `.env.production`**（admin 和 portal 都要改）：
   ```
   VITE_OAUTH_REDIRECT_URI=https://newease.cloud/oauth/callback
   ```
   当前值 `https://admin.sca-skeleton.example.com/oauth/callback` 与新域名不匹配，
   OAuth 回调会被拒。

2. **后端 OAuth2 客户端注册**（`sca-skeleton-auth` 的客户端配置或数据库 `oauth2_registered_client` 表）：
   - `web_sites_redirect_uris` 需包含 `https://newease.cloud/oauth/callback`
   - 旧值 `https://admin.sca-skeleton.example.com/...` 需替换或追加

3. **后端 issuer 配置**（`sca-skeleton-auth-dev.yaml` 或 nacos 配置）：
   - `spring.security.oauth2.authorization-server.issuer` 需为 `https://newease.cloud/auth`
   - 否则 OAuth2 `.well-known` 文档里的端点 URL 仍指向内网 IP，前端调用失败

4. **Nginx 无需改造**：`server_name _` 匹配任意 Host，Cloudflare 转发来的 Host 是 `newease.cloud` 也能命中。

> 这四项是配套改造，缺一不可，否则外网访问会卡在 OAuth 跳转 / token 校验环节。

## 12. SSH 隧道（可选附加）

如果你想通过 Cloudflare Tunnel 远程 SSH 登录服务器（无需开放 22 端口）：

**服务器侧**：在 `config.yml` 的 ingress 段追加一条规则：
```yaml
ingress:
  - hostname: newease.cloud
    service: http://localhost:80

  # 追加：SSH 服务（替换为你的实际域名）
  - hostname: ssh.newease.cloud
    service: ssh://localhost:22

  - service: http_status:404
```

然后建 DNS：
```bash
cloudflared tunnel route dns sca-skeleton ssh.newease.cloud
```

重启服务：
```bash
sudo systemctl restart cloudflared
```

**客户端侧**（你的 macOS）：
1. 安装 cloudflared：`brew install cloudflared`
2. 编辑 `~/.ssh/config`：
   ```
   Host t480
       HostName ssh.newease.cloud
       ProxyCommand cloudflared access ssh --hostname %h
       User root
   ```
3. 直接连接：`ssh t480`

> 推荐：对 SSH 这种敏感服务，到 Cloudflare Zero Trust 后台（https://one.dash.cloudflare.com）
> 的 Access → Applications 添加访问策略（如仅允许特定邮箱登录），避免裸暴露。
