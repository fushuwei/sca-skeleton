# Cloudflare Tunnel 部署步骤（ThinkPad Ubuntu Server）

## ⚠ 必看

本方案中 **只有一处占位符需要你手动替换**，替换后配置即可直接使用：

| 占位符               | 替换为                                         | 出现位置     |
|----------------------|------------------------------------------------|--------------|
| `<YOUR_TUNNEL_UUID>` | 第三步 `cloudflared tunnel create` 返回的 UUID | `config.yml` |

## 1. 安装 cloudflared

```bash
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared-linux-amd64.deb
cloudflared --version
```

## 2. 登录 Cloudflare 账号

```bash
cloudflared tunnel login
```

- 控制台输出一个 `https://dash.cloudflare.com/argotunnel?...` URL
- 复制到浏览器打开 → 登录 Cloudflare → 选择 `newease.cloud` 这个 zone 授权
- 授权成功后服务器生成：`/root/.cloudflared/cert.pem`

验证：

```bash
ls -l /root/.cloudflared/cert.pem
```

## 3. 创建隧道

```bash
cloudflared tunnel create sca-skeleton
```

查看隧道列表确认：

```bash
cloudflared tunnel list
```

## 4. 部署 config.yml

```bash
# 创建目录
mkdir -p /root/.cloudflared/

# 验证替换结果（两处 UUID 必须一致，且与 .json 文件名一致）
grep -E "tunnel:|credentials-file" /root/.cloudflared/config.yml
ls /root/.cloudflared/*.json
```

预期：

```
tunnel: a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx
credentials-file: /root/.cloudflared/a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx.json
```

## 5. 配置 DNS 解析

为 `newease.cloud` 创建 CNAME 记录指向隧道：

```bash
cloudflared tunnel route dns sca-skeleton newease.cloud
```

- 命令成功后，Cloudflare DNS 会自动新增一条 CNAME：`newease.cloud → <UUID>.cfargotunnel.com`
- 到 https://dash.cloudflare.com DNS 面板可看到这条记录（橙色云朵代理开启）

> 若 `newease.cloud` 已有 A/AAAA 记录会冲突，需先在面板删除旧记录。

## 6. 手动测试运行

先手动跑一次，确认无报错再注册系统服务：

```bash
cloudflared tunnel run sca-skeleton
```

预期日志看到 `Registered tunnel connection`（一般 4 条连接）即正常。 浏览器访问 `https://newease.cloud/` 验证页面能打开。 按
`Ctrl+C` 退出。

## 7. 注册为系统服务（开机自启）

```bash
# 自动生成 systemd 单元 + 拷贝 config.yml 到 /etc/cloudflared/
sudo cloudflared service install

# 启用并启动
sudo systemctl enable cloudflared
sudo systemctl start cloudflared

# 查看状态
sudo systemctl status cloudflared
```

预期 `active (running)`。

> `cloudflared service install` 内部行为：
> 1. 把 `/root/.cloudflared/config.yml` 拷贝到 `/etc/cloudflared/config.yml`
> 2. 自动生成 `/etc/systemd/system/cloudflared.service`（无需手写单元文件）
> 3. 注册到 systemd
>
> 因此 **本方案不包含手写 cloudflared.service 文件**，由 `service install` 命令自动生成。

## 8. 验证外网访问

```bash
# 查看实时日志
sudo journalctl -u cloudflared -f

# 从任意外网机器访问（含 https，证书由 Cloudflare 边缘自动签发）
curl -I https://newease.cloud/
curl -I https://newease.cloud/admin/

# 验证 API 反代（需 gateway:9999 已启动）
# OAuth2 token 端点（POST 才返回 token，HEAD 仅验证链路可达）
curl -I https://newease.cloud/api/auth/oauth2/token
curl -I https://newease.cloud/api/actuator/health
```

预期：

- `/`、`/admin/` 返回 `200 OK`（前端 dist 已部署）
- `/auth/...`、`/api/...` 在网关启动后返回 `200 OK`

## 9. 常用运维命令

```bash
# 启停
sudo systemctl start   cloudflared
sudo systemctl stop    cloudflared
sudo systemctl restart cloudflared

# 日志（实时跟踪）
sudo journalctl -u cloudflared -f

# 看最近 200 行
sudo journalctl -u cloudflared -n 200 --no-pager

# 升级 cloudflared
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared-linux-amd64.deb
sudo systemctl restart cloudflared

# 查看隧道列表 / 详情 / 删除
cloudflared tunnel list
cloudflared tunnel info sca-skeleton
# 删除前需先停服务并删 DNS 记录：
#   sudo systemctl stop cloudflared
#   sudo cloudflared service uninstall
#   cloudflared tunnel delete sca-skeleton
```

## 10. SSH 隧道（可选附加）

如果你想通过 Cloudflare Tunnel 远程 SSH 登录服务器（无需开放 22 端口）：

**服务器侧**：在 `config.yml` 的 ingress 段追加一条规则：

```yaml
ingress:
    -   hostname: newease.cloud
        service: http://localhost:80

    # 追加：SSH 服务（替换为你的实际域名）
    -   hostname: ssh.newease.cloud
        service: ssh://localhost:22

    -   service: http_status:404
```

然后建 DNS：

```bash
cloudflared tunnel route dns sca-skeleton ssh.newease.cloud
```

重启服务：

```bash
sudo systemctl restart cloudflared
```

**客户端侧**（你的 macOS）：

1. 安装 cloudflared：`brew install cloudflared`
2. 编辑 `~/.ssh/config`：
   ```
   Host t480
       HostName ssh.newease.cloud
       ProxyCommand cloudflared access ssh --hostname %h
       User root
   ```
3. 直接连接：`ssh t480`

> 推荐：对 SSH 这种敏感服务，到 Cloudflare Zero Trust 后台（https://one.dash.cloudflare.com）
> 的 Access → Applications 添加访问策略（如仅允许特定邮箱登录），避免裸暴露。
