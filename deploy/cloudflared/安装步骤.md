# Cloudflare Tunnel 部署步骤（ThinkPad Ubuntu Server）

> 目标：把本机 Nginx:80 通过 Cloudflare Tunnel 暴露到 `https://newease.cloud`，
> 无需公网 IP、无需开放防火墙端口、流量全程 TLS。
>
> 单域名单入口架构：`newease.cloud` 所有路径统一打到 Nginx:80，由 Nginx 做
> `/admin/`、`/`、`/api/`、`/auth/` 二次分流（复用 prod/nginx 配置，无需改造）。

---

## 0. 前置条件检查

1. **Nginx 已部署并运行**：`curl -I http://localhost:80` 能返回 200（前端 dist 已就位）。
2. **拥有 Cloudflare 账号且 `newease.cloud` 已托管到 Cloudflare DNS**。
   - 登录 https://one.dash.cloudflare.com 确认 zone 存在。
3. **本机有浏览器可完成 OAuth 授权**（`cloudflared login` 会弹出 URL 让你授权）。
   - 纯命令行环境可在本地浏览器打开链接后把 cert.pem 拷贝到服务器（步骤 3 末尾说明）。

---

## 1. 安装 cloudflared（deb 包）

```bash
# 1.1 添加 Cloudflare 官方 GPG key + apt 源
sudo mkdir -p /etc/apt/keyrings/
sudo curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
    -o /etc/apt/keyrings/cloudflare-main.gpg

echo "deb [signed-by=/etc/apt/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared $(lsb_release -cs) main" \
    | sudo tee /etc/apt/sources.list.d/cloudflared.list

# 1.2 安装
sudo apt-get update
sudo apt-get install -y cloudflared

# 1.3 验证
cloudflared --version
which cloudflared    # 应为 /usr/local/bin/cloudflared（deb 包默认软链）
```

> 若官方源拉取慢，可直接下载 deb 包：
> ```bash
> wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
> sudo dpkg -i cloudflared-linux-amd64.deb
> ```

## 2. 登录授权（拿到 cert.pem）

```bash
# 2.1 触发授权流程，弹出 URL
cloudflared tunnel login
```

- 复制控制台输出的 `https://dash.cloudflare.com/argotunnel?...` 链接到浏览器打开
- 在浏览器中选择 `newease.cloud` 这个 zone 进行授权
- 授权成功后，服务器上会生成 `/root/.cloudflared/cert.pem`

**纯命令行环境的替代**：在你本地（macOS）也装一个 cloudflared 执行 `cloudflared tunnel login`，
然后把生成的 `~/.cloudflared/cert.pem` 上传到服务器 `/root/.cloudflared/cert.pem`：
```bash
scp ~/.cloudflared/cert.pem root@192.168.1.105:/root/.cloudflared/cert.pem
```

验证：
```bash
ls -l /root/.cloudflared/cert.pem
```

---

## 3. 创建 Tunnel

```bash
# 3.1 创建 tunnel（命名 sca-skeleton，名字随意但需记住）
cloudflared tunnel create sca-skeleton
```

输出示例：
```
Created tunnel sca-skeleton with id  <TUNNEL_UUID>
Tunnel credentials written to /root/.cloudflared/<TUNNEL_UUID>.json
```

记下 `<TUNNEL_UUID>`，下一步要用。验证：
```bash
ls /root/.cloudflared/
# 应有 cert.pem  <TUNNEL_UUID>.json
cloudflared tunnel list    # 列出所有 tunnel 及其 UUID
```

---

## 4. 绑定 DNS 路由（创建 CNAME）

```bash
# 4.1 把 newease.cloud → <TUNNEL_UUID>.cfargotunnel.com 自动建 CNAME 记录
cloudflared tunnel route dns sca-skeleton newease.cloud
```

- 命令成功后 Cloudflare DNS 会自动新增一条 CNAME：`newease.cloud → <UUID>.cfargotunnel.com`
- 到 https://dash.cloudflare.com DNS 面板可看到这条记录（橙色云朵代理开启）

> 若 `newease.cloud` 已有 A/AAAA 记录会冲突，需要先在面板删除旧记录。

---

## 5. 部署 config.yml

```bash
# 5.1 创建配置目录（已存在则跳过）
mkdir -p /root/.cloudflared/

# 5.2 上传本目录的 config.yml 到服务器
#     在本地（macOS）执行：
#     scp deploy/cloudflared/config.yml root@192.168.1.105:/root/.cloudflared/config.yml

# 5.3 把模板里的 <替换为你的 TUNNEL_UUID> 替换为真实 UUID
sed -i "s/<替换为你的 TUNNEL_UUID>/你的真实UUID/g" /root/.cloudflared/config.yml
# 例如：sed -i "s/<替换为你的 TUNNEL_UUID>/a1b2c3d4-.../g" /root/.cloudflared/config.yml

# 5.4 验证替换结果（两处 UUID 必须一致）
grep -E "tunnel:|credentials-file" /root/.cloudflared/config.yml
```

预期输出：
```
tunnel: a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx
credentials-file: /root/.cloudflared/a1b2c3d4-xxxx-yyyy-zzzz-xxxxxxxxxxxx.json
```

## 6. 注册 systemd 服务

```bash
# 6.1 上传 cloudflared.service 到 systemd 目录
#     在本地（macOS）执行：
#     scp deploy/cloudflared/cloudflared.service root@192.168.1.105:/etc/systemd/system/cloudflared.service

# 6.2 重载 systemd 配置
sudo systemctl daemon-reload

# 6.3 启用并启动
sudo systemctl enable cloudflared
sudo systemctl start cloudflared

# 6.4 查看状态
sudo systemctl status cloudflared
```

预期 `active (running)`，日志里看到 `Registered tunnel connection` 即正常。

## 7. 验证外网访问

```bash
# 7.1 查看实时日志（关键排查手段）
sudo journalctl -u cloudflared -f

# 7.2 从任意外网机器访问（含 https，证书由 Cloudflare 边缘自动签发）
curl -I https://newease.cloud/
curl -I https://newease.cloud/admin/

# 7.3 验证 API 反代（需 gateway:9999 已启动）
curl -I https://newease.cloud/auth/oauth2/.well-known/oauth-authorization-server
curl -I https://newease.cloud/api/actuator/health
```

预期：
- `/`、`/admin/` 返回 `200 OK`
- `/auth/...`、`/api/...` 在网关启动后返回 `200 OK`

## 8. 常用运维命令

```bash
# 启停
sudo systemctl start   cloudflared
sudo systemctl stop    cloudflared
sudo systemctl restart cloudflared

# 看日志（实时跟踪）
sudo journalctl -u cloudflared -f

# 看最近 200 行
sudo journalctl -u cloudflared -n 200 --no-pager

# 升级 cloudflared
sudo apt-get update && sudo apt-get install --only-upgrade cloudflared

# 查看 tunnel 列表 / 删除
cloudflared tunnel list
cloudflared tunnel delete sca-skeleton    # 删除前需先停服务并删 DNS 记录
```

## 9. 关键设计说明（审核重点）

1. **单域名单入口**：所有流量走 `newease.cloud → Nginx:80`，Nginx 内部做 `/admin/`、`/`、`/api/`、`/auth/` 二次分流。复用 prod/nginx 配置，零改造。
2. **不开放公网端口**：cloudflared 只出站连接 Cloudflare 边缘节点，无需在防火墙开 80/443，比传统反向代理更安全。
3. **systemd 托管**：`Restart=on-failure` 异常自愈，开机自启。与 nginx 容器 `restart:no` 不冲突（一个管容器，一个管进程）。
4. **config.yml 路径约定**：放 `/root/.cloudflared/config.yml`，与 `cert.pem`、`credentials.json` 同目录，cloudflared 默认查找路径。
5. **catch-all 404**：ingress 最后一条 `service: http_status:404`，未匹配 Host 直接拒绝，防止裸跑其它域名。

## 10. ⚠ 重要提醒：前端与后端需同步调整

cloudflared 把外网入口从 `192.168.1.105` 变成 `https://newease.cloud`，OAuth2 / 前端相关配置需要相应更新（这些是代码层面，需你手动改，本方案只列清单）：

1. **前端 `.env.production`**（admin 和 portal 都要改）：
   ```
   VITE_OAUTH_REDIRECT_URI=https://newease.cloud/oauth/callback
   ```
   当前值 `https://admin.sca-skeleton.example.com/oauth/callback` 与新域名不匹配，
   OAuth 回调会被拒。

2. **后端 OAuth2 客户端注册**（`sca-skeleton-auth` 的客户端配置或数据库 `oauth2_registered_client` 表）：
   - `web_sites_redirect_uris` 需包含 `https://newease.cloud/oauth/callback`
   - 旧值 `https://admin.sca-skeleton.example.com/...` 需替换或追加

3. **后端 issuer 配置**（`sca-skeleton-auth-dev.yaml` 或 nacos 配置）：
   - `spring.security.oauth2.authorization-server.issuer` 需为 `https://newease.cloud/auth`
   - 否则 OAuth2 `.well-known` 文档里的端点 URL 仍指向内网 IP，前端调用失败

4. **Nginx 无需改造**：`server_name _` 匹配任意 Host，Cloudflare 转发来的 Host 是 `newease.cloud` 也能命中。

> 这四项是配套改造，缺一不可，否则外网访问会卡在 OAuth 跳转 / token 校验环节。
