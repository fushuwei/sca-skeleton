# Cloudflared Tunnel 完整安装步骤

**服务器：** 192.168.1.105 (Ubuntu Server)
**域名：** newease.cloud **前置条件：**

- 已安装 mihomo (Clash) 代理服务
- mihomo 配置了 SOCKS5 端口（默认 7891）
- 在阿里云已购买域名 newease.cloud

## 一、安装 cloudflared

```bash
# 下载最新版
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb

# 执行安装
sudo dpkg -i cloudflared-linux-amd64.deb

# 验证版本
cloudflared --version
```

## 二、登录 Cloudflare 授权

```bash
cloudflared tunnel login
```

执行后会生成 URL，在浏览器访问并授权：

1. 打开终端显示的 URL（如 https://dashboard.cloudflare.com/...）
2. 登录 Cloudflare 账号
3. 选择 newease.cloud 域名
4. 授权成功后，会在 /root/.cloudflared/ 生成 cert.pem

## 三、创建隧道

```bash
cloudflared tunnel create thinkpad-tunnel
```

**记下返回的 Tunnel ID (UUID)**，后续配置需要使用。

示例输出：

```
Created tunnel thinkpad-tunnel with id <YOUR_TUNNEL_ID>
```

## 四、创建隧道配置文件

创建 /etc/cloudflared/config.yml：

```yaml
tunnel: <YOUR_TUNNEL_ID>
credentials-file: /root/.cloudflared/<YOUR_TUNNEL_ID>.json
protocol: http2
loglevel: warn

ingress:
    # 1. SSH 远程访问：ssh.newease.cloud -> 22 端口
    - hostname: ssh.newease.cloud
      service: ssh://localhost:22

    # 2. 项目 sca-skeleton：newease.cloud -> 8080 端口
    - hostname: newease.cloud
      service: http://localhost:8080

    # 3. 兜底规则（必须保留）
    - service: http_status:404
```

## 五、配置代理（中国网络环境必需）

### 5.1 确认 mihomo 已启动

```bash
systemctl start mihomo
systemctl status mihomo

# 查看 SOCKS5 端口（通常是 7891）
ss -tlnp | grep mihomo
```

### 5.2 安装并配置 tsocks

```bash
apt-get install -y tsocks
```

创建 /etc/tsocks.conf：

```ini
server = 127.0.0.1
server_port = 7891
server_type = 5

# 本地网络不走代理
local = 192.168.0.0/255.255.0.0
local = 10.0.0.0/255.0.0.0
local = 172.16.0.0/255.240.0.0
local = 127.0.0.0/255.0.0.0

reuse = yes
```

### 5.3 测试隧道连接

```bash
killall cloudflared 2>/dev/null
tsocks cloudflared tunnel --edge-ip-version 4 run thinkpad-tunnel
```

如果成功，会看到：

```
CONNECTOR ID                         CREATED              EDGE
e06caf40-xxxx-xxxx-xxxx-xxxx 2026-07-27T07:30:18Z 2xlax01, 1xlax08
```

按 Ctrl+C 停止测试。

## 六、配置 DNS 路由

**推荐方案：阿里云 DNS**（稳定、快速，几分钟生效）

### 6.1. 确保 Nameserver 在阿里云

如果在 Cloudflare 后台已经修改了 Nameserver，需要改回阿里云：

1. 登录阿里云域名管理页面（https://dc.console.aliyun.com/）
2. 选择域名 `newease.cloud`
3. 点击 **"DNS 修改"**（注意：不是"DNS 设置"）
4. 将 Nameserver 修改为阿里云：
   ```
   dns25.hichina.com
   dns26.hichina.com
   ```
5. 点击 **"确定"** → 点击 **"同步"**

等待 DNS 传播（通常几分钟）。

验证：

```bash
dig +short newease.cloud NS @8.8.8.8
# 应返回 dns25.hichina.com 和 dns26.hichina.com
```

#### 6.2 在阿里云添加 CNAME 记录

1. 登录阿里云域名管理页面（https://dc.console.aliyun.com/）
2. 选择域名 `newease.cloud`
3. 点击 **"DNS 设置"**（不是"DNS 修改"）
4. 点击 **"添加记录"**

**添加两条 CNAME 记录：**

**记录 1：**

- 记录类型：CNAME
- 主机记录：`@`（表示 newease.cloud 本身）
- 记录值：`<YOUR_TUNNEL_ID>.cfargotunnel.com`
- TTL：10 分钟
- 线路：默认

**记录 2：**

- 记录类型：CNAME
- 主机记录：`ssh`
- 记录值：`<YOUR_TUNNEL_ID>.cfargotunnel.com`
- TTL：10 分钟
- 线路：默认

> **注意：** 将 Tunnel ID 替换为你的实际值。

#### 6.3 验证 DNS 生效

等待几分钟后，验证：

```bash
dig +short newease.cloud @223.5.5.5
```

期望输出：

```
104.21.24.77
172.67.217.201
```

这些是 Cloudflare CDN 的 IP 地址。

### 备选方案：Cloudflare DNS

> **说明：** 本次部署实际使用的是这个方案（修改 Nameserver 到 Cloudflare），但 DNS 传播需要 24-48 小时（国内通常几小时）。

#### 6.1 在 Cloudflare 后台添加域名

1. 访问 https://dash.cloudflare.com
2. 点击 **Add a Site**
3. 输入域名 `newease.cloud`
4. 选择 **Free 计划**
5. Cloudflare 会扫描现有 DNS 记录，点击 **Continue**
6. Cloudflare 会提供两个 Nameserver（如 `dimitris.ns.cloudflare.com`, `mckinley.ns.cloudflare.com`）

#### 6.2 在阿里云修改 Nameserver

1. 登录阿里云域名管理页面（https://dc.console.aliyun.com/）
2. 选择域名 `newease.cloud`
3. 点击 **"DNS 修改"**（注意：不是"DNS 设置"）
4. 在"当前 DNS 服务器"区域，点击 **"修改 DNS 服务器"** 按钮
5. 删除现有的阿里云 Nameserver：
   ```
   dns25.hichina.com
   dns26.hichina.com
   ```
6. 输入 Cloudflare 提供的 Nameserver：
   ```
   dimitris.ns.cloudflare.com
   mckinley.ns.cloudflare.com
   ```
7. 点击 **"确定"** 或 **"保存"**
8. 点击 **"同步"** 按钮（手动触发 DNS 刷新）

#### 6.3 在 Cloudflare 后台添加 CNAME 记录

1. 在 Cloudflare 后台，选择 `newease.cloud`
2. 左侧菜单： **DNS** → **Records**
3. 点击 **Add record**

**添加两条 CNAME 记录：**

**记录 1：**

- 类型：CNAME
- 名称：`newease.cloud`（或 @）
- 目标：`<YOUR_TUNNEL_ID>.cfargotunnel.com`
- 代理状态：✅ 已代理（橙色云）
- TTL：自动

**记录 2：**

- 类型：CNAME
- 名称：`ssh.newease.cloud`
- 目标：`<YOUR_TUNNEL_ID>.cfargotunnel.com`
- 代理状态：✅ 已代理（橙色云）
- TTL：自动

> **注意：** 代理状态必须是 **橙色云**（已代理），不是灰色云（仅 DNS）。

#### 6.4 等待 DNS 传播

**重要提示：**

- DNS 修改后有 **24-48 小时**全球 DNS 生效时间
- 但在国内，通常 **几分钟到几小时** 就能生效
- Cloudflare 后台会在这期间显示"挂起"状态，这是正常的

#### 6.5 验证 DNS 生效

```bash
# 检查 Nameserver 是否已改为 Cloudflare
dig +short newease.cloud NS @8.8.8.8

# 期望输出（成功后）：
# dimitris.ns.cloudflare.com.
# mckinley.ns.cloudflare.com.
```

```bash
# 检查 DNS 解析
dig +short newease.cloud @8.8.8.8

# 期望输出（成功后）：
# 104.21.24.77
# 172.67.217.201
```

这些是 Cloudflare CDN 的 IP 地址。

### 方案对比

| 对比项                  | 推荐方案 B（阿里云）      | 备选方案 A（Cloudflare）    |
|:------------------------|:--------------------------|:----------------------------|
| **需要修改 Nameserver** | ❌ 不需要                 | ✅ 需要                     |
| **生效时间**            | ✅ 几分钟                 | ⚠️ 24-48 小时（国内几小时） |
| **国内 DNS 稳定性**     | ✅ 稳定                   | ⚠️ 可能被污染/劫持          |
| **国内访问速度**        | ✅ 快                     | ⚠️ 一般                     |
| **全球访问速度**        | ⚠️ 慢                     | ✅ 快（CDN）                |
| **安全性**              | ⚠️ 基础防护               | ✅ CDN 防护、WAF            |
| **推荐场景**            | ✅ **国内访问、快速上线** | 长期使用、全球访问          |

**为什么推荐阿里云 DNS？**

1. **国内 DNS 稳定可靠**：阿里云 DNS 在国内有完整基础设施，不容易被污染
2. **几分钟内生效**：不需要等待 24-48 小时的全球传播
3. **不依赖 Cloudflare 的 DNS**：即使 Cloudflare 被墙，域名解析依然正常
4. **适合大多数国内场景**：如果你的用户主要在国内，这个方案更合适

**什么时候用 Cloudflare DNS（方案 A）？**

- 需要 Cloudflare 的 CDN、WAF、DDoS 防护等完整功能
- 有全球访问需求
- 不急于上线（可等待 DNS 传播）

## 七、配置 systemd 服务

### 7.1 创建服务覆盖配置

创建 /etc/systemd/system/cloudflared.service.d/override.conf：

```ini
[Unit]
After=mihomo.service
Requires=mihomo.service

[Service]
ExecStart=
ExecStart=/usr/bin/tsocks /usr/bin/cloudflared --no-autoupdate --config /etc/cloudflared/config.yml tunnel run

# 必须用 Restart=always，不能用默认的 on-failure：
# cloudflared 在网络抖动/mihomo 重启等场景下可能正常退出（exit status=0/SUCCESS），
# on-failure 不会处理 status=0 的退出，导致服务停止后无法自愈（Cloudflare Error 1033）。
# always 不区分退出码，任何退出都自动重启。
Restart=always
RestartSec=30s
```

### 7.2 启动服务

```bash
systemctl daemon-reload
systemctl enable --now cloudflared
```

## 十、配置 Nginx（可选）

> 说明：以下两项 Nginx 修改是 cloudflared + Nginx 架构下的常见坑点，已沉淀在 `deploy/nginx/conf.d/sca-skeleton.conf` 中，按需同步到服务器即可。

### 10.1 修改 /admin 重定向（避免跳转到 :8080）

```nginx
# 修改前（相对路径）
location = /admin {
    return 301 /admin/;
}

# 修改后（绝对 URL）
location = /admin {
    return 301 https://$host/admin/;
}
```

**为什么必须用绝对 URL：**

Nginx 对相对路径的 `return 301 /admin/` 会用 `$scheme://$host:$server_port` 拼绝对 URL。在本架构中：

- `$server_port = 8080`（Nginx 容器监听端口）
- `$scheme = http`（cloudflared → Nginx 走 HTTP，Cloudflare 边缘才做 HTTPS 终止）

浏览器收到的 `Location` 头会是 `http://newease.cloud:8080/admin/`，导致：

1. 暴露内网端口 8080
2. HTTP 协议被浏览器拒绝（HSTS / Cloudflare Always-Use-HTTPS 已强制 HTTPS）
3. Cloudflare Error 1033（边缘无法回源到 8080 端口）

用 `https://$host/admin/` 显式指定协议和域名，绕开 `$server_port` 和 `$scheme` 的默认拼接。

### 10.2 修复 OPPO Sans TTF 字体 MIME 类型

```nginx
# 新增 /fonts/ location 块
location /fonts/ {
    root /usr/share/nginx/html/portal;
    default_type font/ttf;
    try_files $uri =404;
}
```

**为什么需要这个修复：**

Nginx 默认 `mime.types` 不包含 `.ttf` 扩展名映射，导致 OPPO Sans 22MB TTF 字体被当作 `application/octet-stream` 返回。配合 `X-Content-Type-Options: nosniff` 响应头，浏览器直接拒绝加载该字体，登录页 body 文本回退到系统默认字体（视觉效果差，与设计稿不一致）。

用 `default_type font/ttf` 而不是 `types { }` 块，避免覆盖继承的 MIME 表（`.woff2` 仍走 `font/woff2`）。

> 注意：Material Icons / Material Symbols 字体通过 `@quasar/extras` 打包到 `/assets/*.woff2`，由 nginx mime.types 默认映射为 `font/woff2`，无需额外配置。

### 10.3 同步到 105 服务器并 reload

```bash
# 复制配置到 105
scp deploy/nginx/conf.d/sca-skeleton.conf root@105:/data/projects/sca-skeleton/deploy/nginx/conf.d/

# 或复制到 Docker 容器配置
scp deploy/nginx/conf.d/sca-skeleton.conf root@105:/data/docker/containers/nginx/conf.d/

# Reload Nginx
docker exec nginx nginx -s reload
# 或
systemctl reload nginx
```
