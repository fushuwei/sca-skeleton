# SCA Skeleton Nginx 部署步骤（ThinkPad Ubuntu Server）

> 目标服务器：`192.168.1.105`，部署目录：`/data/docker/containers/nginx`
> 本目录文件全部拷贝到上述服务器目录后执行下列命令。本步骤仅安装并配置 Nginx，
> 不安装/修改其它任何服务（gateway / auth / system / 前端 dist 由你手动部署）。

---

## 0. 目录结构说明

拷贝到服务器后的目标布局（与 redis / mysql / nacos 命名风格一致）：

```
/data/docker/containers/nginx/
├── docker-compose.yml        # 容器编排
├── conf/
│   └── nginx.conf            # Nginx 主配置
├── conf.d/
│   └── sca-skeleton.conf     # 站点配置（server 块）
├── html/
│   ├── admin/                # ← 放置 admin 打包后的 dist 内容
│   └── portal/               # ← 放置 portal 打包后的 dist 内容
└── logs/                     # Nginx 日志（自动生成）
```

路径映射关系（compose volumes）：

| 宿主机路径 | 容器内路径 | 用途 |
| --- | --- | --- |
| `./conf/nginx.conf` | `/etc/nginx/nginx.conf` | 主配置 |
| `./conf.d` | `/etc/nginx/conf.d` | 站点配置 |
| `./html` | `/usr/share/nginx/html` | 前端静态资源 |
| `./logs` | `/var/log/nginx` | 日志 |

## 1. 上传配置到服务器

在本地（macOS）执行，把整个 `prod` 目录传到服务器：

```bash
# 在项目根目录 sca-skeleton 下执行
scp -r deploy/nginx/prod root@192.168.1.105:/data/docker/containers/nginx
```

> 也可用 rsync：`rsync -avz deploy/nginx/prod/ root@192.168.1.105:/data/docker/containers/nginx/`

---

## 2. 服务器端校验目录

SSH 登录服务器后确认文件就位：

```bash
ssh root@192.168.1.105

# 确认结构
ls -R /data/docker/containers/nginx
```

应能看到 `docker-compose.yml`、`conf/`、`conf.d/`、`html/admin`、`html/portal`、`logs/`。

---

## 3. 部署前端 dist（你手动操作）

> Nginx 配置已就绪，但 `html/admin`、`html/portal` 当前为空。
> 你需自行打包前端并把 dist 内容拷进去，否则访问会 404。

```bash
# 假设你已在本机打包：
#   admin  → pnpm --filter admin build    （产物在 apps/admin/dist）
#   portal → pnpm --filter portal build  （产物在 apps/portal/dist）

# 上传 admin 产物（注意：dist 内容直接落到 admin 目录下，能直接看到 index.html）
scp -r sca-skeleton-frontend/apps/admin/dist/* root@192.168.1.105:/data/docker/containers/nginx/html/admin/

# 上传 portal 产物
scp -r sca-skeleton-frontend/apps/portal/dist/* root@192.168.1.105:/data/docker/containers/nginx/html/portal/
```

服务器端验证：

```bash
ls /data/docker/containers/nginx/html/admin/    # 应能看到 index.html
ls /data/docker/containers/nginx/html/portal/   # 应能看到 index.html
```

> 提示：admin 使用 `base=/admin/`，portal 使用根路径 `/`，nginx 已按此配置 try_files 回退。

## 4. 启动 Nginx 容器

```bash
cd /data/docker/containers/nginx

# 拉取镜像 + 后台启动
docker compose up -d

# 查看容器状态
docker compose ps

# 查看启动日志（排查配置错误）
docker compose logs nginx
```

---

## 5. 验证配置与连通性

```bash
# 5.1 容器内校验 nginx 语法
docker exec nginx nginx -t

# 5.2 验证 host.docker.internal 能否解析到宿主机
#     （网关未启动时 upstream 会 502，属正常现象）
docker exec nginx getent hosts host.docker.internal

# 5.3 验证前端页面（应返回 index.html）
curl -I http://192.168.1.105/
curl -I http://192.168.1.105/admin/

# 5.4 验证网关反代（先启动 gateway:9999，再测）
curl -I http://192.168.1.105/auth/oauth2/.well-known/oauth-authorization-server
curl -I http://192.168.1.105/api/actuator/health
```

预期：
- `/`、`/admin/` 返回 `200 OK`（前端 dist 已部署）
- `/auth/...`、`/api/...` 在网关启动后返回 `200 OK`
- 网关未启动时返回 `502 Bad Gateway`（Nginx upstream 连不上宿主机 :9999）

## 6. 常用运维命令

```bash
cd /data/docker/containers/nginx

# 停止
docker compose down

# 重启（修改配置后）
docker compose restart

# 改配置后重新加载（不停机，最常用）
docker exec nginx nginx -s reload

# 语法检查（改完配置先校验）
docker exec nginx nginx -t

# 查看实时访问日志
docker exec nginx tail -f /var/log/nginx/sca-skeleton.access.log

# 查看错误日志
docker exec nginx tail -f /var/log/nginx/sca-skeleton.error.log
```

## 7. 关键设计说明（审核重点）

1. **唯一入口**：Nginx:80 是系统唯一公网入口，网关/认证/业务服务不直接暴露。
2. **网关访问方式**：容器内通过 `host.docker.internal`（compose `extra_hosts` 注入 `host-gateway`）访问宿主机 :9999 网关，避免硬编码 IP，IP 变更无需改配置。
3. **API 剥离前缀**：`/api/xxx` → 网关 `/xxx`（`rewrite ^/api(/.*)$ $1 break`），与开发环境 Vite 代理一致。
4. **auth 保留前缀**：`/auth/` → 网关 `/auth/`（`proxy_pass` 无尾斜杠保留前缀），匹配网关路由 `Path=/auth/**`。
5. **身份头边界清理**：反代网关时显式清空 `X-User-Id` 等内部身份头，与网关 `RequestHeaderGovernanceGlobalFilter` 双重防护，防伪造。
6. **X-Forwarded-For 链**：由 `$proxy_add_x_forwarded_for` 自动追加，网关用 `maxTrustedIndex(1)` 取首个 IP。
7. **SPA 回退**：admin `try_files` 回退到 `/admin/index.html`，portal 回退到 `/index.html`，支持前端路由刷新不 404。
8. **restart: no**：按要求，容器不会自动重启，宿主机重启后需手动 `docker compose up -d`。
9. **actuator 内网限制**：监控端点仅允许 RFC 1918 私网网段访问。

> 如需 HTTPS / 域名 / SSL 证书，需另起一套 server 块（可参考 `deploy/nginx/default.conf`），当前内网场景默认 HTTP。
